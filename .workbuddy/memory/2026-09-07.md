## 架构重构（同日，用户要求「先重构框架」）

用户反馈后要求优先重构，目标：架构合理 / 扩展性 / 容错 / 易开发 / **加鱼方便**。

### 采用策略：兼容式重构
保留 `constants.ts`（re-export data/）、`types.ts`（结构+类型转发）、`gameEngine.ts`（薄编排器，导出名不变）三个门面，
因此 `GameCanvas` / `UIOverlay` / `MiniMap` / 原有测试**一行未改**，零风险落地。这个策略值得复用。

### 新结构
- `src/data/`：creatures（加鱼唯一入口）/ skills / biomes / buildings / world —— 纯数据零依赖
- `src/core/`：math（NaN 免疫）/ errors（safe 包装，连续失败自动摘除系统）/ EventBus
- `src/systems/`：index（注册表，顺序即执行顺序）/ terrain / spawn / playerControl / ai / skills / world / items / combat / events / progression
- `src/factories/initialState.ts`：从 App.tsx 抽出，运行时与测试共用

### 关键设计（可复用）
1. **类型从数据推导**：`type CreatureType = keyof typeof CREATURE_DATA` + 同名常量对象，`CreatureType.X` 语法兼容 enum，加数据即加类型。BiomeType / SkillId / BuildingType 同理。
2. **注册表代替 if-else**：技能从 20 个中文字符串 `if` 改成 `SKILL_HANDLERS[SkillId]`，AI 从「全追玩家」改成 `AI_HANDLERS[behavior]`。
3. **启动自检**：`validateCreatures()` + `validateSkills()` 在第一帧跑，明确列出「声明未实现」项 —— 魔鬼鱼「毒刺」静默失效这类问题以后开发期就会暴露。
4. **safe() 容错**：每个系统被包装，抛错只记录，连续失败 3 次自动摘除，不掀翻游戏循环。

### 已接线的断线功能
生态区加成（currentBiome 每帧更新）/ 障碍物渲染+碰撞 / 建筑渲染+交互 / 传送门传送 / 陨石事件 / AI 六行为分发 + 鱼与鱼互吃。

### 顺带修掉的 Bug
宝藏计时（预告 6s→3s、存活 7s→10s）/ labels 内存泄漏 / 宝藏生成取等判断跳帧失效 / vite.config 死配置 / e2e 引用未定义变量。
另：加障碍物碰撞后必须同步加渲染，否则玩家撞隐形墙（差点踩坑，已补 drawObstacle / drawBuilding）。

## P1 完成（同日晚 · 战斗深度）

用户「继续」，P1 四项全部完成，验证：tsc 0 错误 · **145 测试全绿**（新增 19 个）· vite build 通过。

1. **P1-1 撕咬取代一击必杀**：`systems/combat.ts` 的 processCollision 改为三步——撕咬扣血（`BITE_DAMAGE_MULT` × 体型差 sizeFactor，背刺 ×1.5）→ 大鱼反击 → 判定死亡。新增 `COMBAT_CONFIG`（撕咬冷却 18 帧 / 吞噬血线 30% / 体型缩水 0.995）。
