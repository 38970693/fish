## git 修复：从「提交不了」到可用（同日 08:10）

### 症状

`git status` / `git commit` 全部报 `fatal: unable to read tree (6c16b25...)`。

### 根因（两层，别只修一层）

1. **`.git/index` 的 cache-tree 指向已丢失的 tree**
   → `git status` 一上来就炸。修法：`mv .git/index .git/index.corrupt-bak` 后 `git add -A` 重建。
2. **HEAD 那棵 tree 本身就缺子树**（`9cb927ee` → `src` → `6c16b25` 对象在 09-08 事故中丢失）
   → 重建索引后 status 仍炸。这个**修不了**（对象没了）。
   但 `git commit` 其实不需要读父提交的 tree——所以**直接提交就能绕过**，
   提交后 HEAD 指向完整的新 tree，status 自然恢复。（提交时那句 fatal 是噪音，看退出结果即可。）

### 关键发现：25 个历史 commit 内容全损

逐个 `git ls-tree -r <c>` 探测：**只有新提交可读，25 个老 commit 全部 BROKEN**。
那段历史只剩 commit message，任何 `show` / `diff` / `checkout` 都取不到内容。

### 处理：断开并归档（用户选的）

- `archive-broken-history` → 20da1e7（保留 26 条 message 供查）
- `dev` → **3281854**，用 `git commit-tree $(git rev-parse HEAD^{tree})` 造的**无父根提交**
  （tree 完全一样，所以工作区/索引不用动，零风险）
- 解除了 dev 对 `origin/dev` 的上游跟踪（否则一直显示 `[ahead 1, behind 26]`）

现在 `git show --stat` / `log -p` / `write-tree` / `status` 全部正常，76 文件 15124 行。

### ⚠️ 新坑：嵌套 ref（带 `/` 的分支名）会被 git 静默删除

用户一句「nest」让我去深挖，结论比"建目录失败"严重得多：

**`git branch a/b` 和 `git update-ref refs/heads/a/b` 会把 ref 文件和父目录一起删掉，然后 exit 0 假装成功。**

排查过程（都是对照实验）：

1. `mkdir -p .git/refs/heads/archive` 成功 → 不是 mkdir 权限问题
2. 跑 `git branch archive/broken-history` 后目录**消失** → 是 git 的回滚把它删了
3. 手册写 `echo <sha> > .git/refs/heads/archive/broken-history` → **git 能正常读**（`rev-parse` 返回 20da1e7）
   → 读没问题，纯写的问题
4. 预建 `.git/logs/refs/heads/archive/` 后再 update-ref → **reflog 写成功（462B），ref 文件没有**
   → git 走到了"写 reflog → 写 ref 失败 → 回滚删目录"这条路径，但错误码吞了
5. 最后用非法内容做了一次，才逼出真报错：
   `cannot lock ref ...: unable to resolve reference ...: reference broken`
6. 换成合法 SHA 再 update-ref → **文件被删、目录被删、exit 0**

排查排除了：hooks（全是 .sample，无 core.hooksPath）、reftable 后端（format 0，files 后端）、
packed-refs 干扰、目录不存在（先建好一样被删）。

git 是 WorkBuddy 自带 **PortableGit 2.55.0**（`C:/Users/38970/.workbuddy/binaries/PortableGit/...`），
机器上没有第二个 git 可对照。

**规避：这台机器一律用扁平分支名**（`archive-broken-history`）。
真的要嵌套就手写文件，但千万别再让 git 去写它。

### 遗留

- `main`(0f5a8df) 和 `test`(3694dd0) 两个分支仍指向损坏 commit，checkout 会炸。没删，待用户决定。

### 实拍又揪出两个真缺陷（23:16）

拍切换瞬间的截图时，HUD 显示 `玩家 (电鳗) Lv.3` —— 换身体把等级也带走了。顺着查下去发现两个问题：

**① `level` 被当成身体属性，和代码自己的注释打架。**
`squad.ts` 注释白纸黑字写着「灵魂层面的东西（weight / evolutionPoints / score / 技能）不动」，
但 `moveBody` 里有一行 `to.level = from.level`，`possessMember` 又 `player.level = memberBody.level`。
而 level 的真实用途：
- `combat.ts` 吃鱼推进：`level = floor(weight/10)+1`（**weight 是灵魂属性**）
- `skills.ts:471` 解锁流派技能：`index = floor(level/3)-1` → Lv3 第 1 个 / Lv6 第 2 个……
- `skills.ts:511` 门控右键主技能：`level >= UNLOCK_LEVEL`

**后果**：附身一条 t1 小鱼（Lv1）时 `index` 算成 **-1 → 已解锁的 Q 技能当场消失**；
而且 level 和保留下来的 weight 直接失配。
**修法**：`moveBody` 不再搬 level（身体只剩 种类/体型/血量/外观/速度）；
成员接管旧身体时显式 `member.level = player.level`；玩家接管新身体时不动 level。

**② 遮罩态下按 R 仍能换身体。**
keydown 挂在 `window` 上，进化选择 / 结算 / 商场这些**暂停态**里 R 照样生效，
等于能在弹窗背后偷偷换身体。**修法**：`switchToNextMember` 开头加 `status === PLAYING` 门闸。
