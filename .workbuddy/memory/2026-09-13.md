## 修复「鱼原地转圈圈」复发（第二味药，用户报「还是会有」）

- 上次（3.4.1）只治了「距离边界两侧互抢方向盘」的停泊带，这次逐帧取证发现**另有两条病根**：
  1. **`atan2` 奇点**：实体之间**没有分离力、可以互相重叠**。追/逃双方贴到几乎重合时，
     相对位移抖动一丁点方位角就翻半圈 → 鱼每帧以最大敏捷转向、转弯半径 < 1px。
     实测磷虾 0.84 rad/帧、乌龟 1.44 rad/帧（≈满敏捷×π），1200 帧上百圈，路程 450px 净位移 12px。
  2. **锁定抖动**：若干条威胁距离相近时「最近的那条」每帧易主，方位角每两帧跳 ~2 rad。
- **取证手法（很值钱，以后照抄）**：①先跑真实 updateGame 帧循环 + 钉随机种子，按实体累计
  「角扫掠 / 路程 / 净位移」→ 定位最坏个体；②给目标实体的 `angle` 装 `Object.defineProperty`
  setter 抓**每帧写入次数与调用栈** → 证明「每帧只写 1 次」，排除两个系统互抢方向盘；
  ③用 `Δ角 ÷ agility` 反推角差 ≈ −π → 锁定「目标方位角进入奇点」。
  ⚠️ 抓栈时过滤要用 `includes('systems')` 之类，**别用 `/src/`** —— Windows 栈里是反斜杠。
- **修法**（`src/systems/ai.ts`）：①`isOverlapping()` 双方圆相交时不再追方位角、保持朝向直冲；
  ②`TARGET_HYSTERESIS_SQ = 1.25²` 锁定迟滞（记忆存新增可选字段 `Entity.lockId`，
  **不复用 targetId** —— 那个会被「混乱」技能改写；隐蔽仍一票否决，大鱼反制探测不写回）。
- **判据升级**：改用**转弯半径 = 路程 ÷ 角扫掠**，而不是「转了几圈」—— 绕大圈的鱼转再多圈也正常。
  修复前最坏 90.9 圈/半径 0.79px → 修复后 6.4 圈/半径 49.7px。
- 回归测试 `src/__tests__/orbit.test.ts` 3 例，并做了**反向验证**（分别关掉两味药都失败：
  关重叠 → PLANKTON 转20.7圈半径0.9px；关迟滞 → BLUE_TANG 半径11.6px 越线）。
  ⚠️ 重叠判定**只用半径和、不加余量**是刻意的：加 24px 会吞掉 concealment 的
  「贴脸识破隐蔽」用例（双髻鲨 radius 50，用例摆在 75px 处）。

## 修复「撞障碍物顿挫」（用户报「遇到障碍物会顿挫」）

- **根因**：`src/systems/terrain.ts` 的 `resolveObstacles` 只把实体**推出**障碍物、**从不改朝向**。
  而 AI/玩家每帧先朝目标推进（`moveForward` 按当前朝向设速度再位移），目标在岩石另一侧时
  这一帧就是「扎进石头里」，推挤再顶回表面 → 净位移为零，实体**顶死在石头上**（尾巴还在摆）。
  实测（400 帧）：玩家贴面 **387 帧、绕行扫掠 0.00 rad**；鱼 799/900 帧。
- **关键不对称（本轮最大收获）**：地图边界 `clampToMap` **早就**算了切向做平滑
  （外层反射向内 + `entity.angle = angleToCenter + (angle-angleToCenter)*0.6` + 软限速挡），
  障碍物这边一直没跟上。**「边界做了平滑、障碍物没做」是同类 bug 的通用怀疑点** —— 改碰撞前
  先对照另一条约束通路是否已有成熟处理，直接搬。
- **治法**（三段）：①推到表面；②朝向按**切向**掰 —— 切向基 `(-ny, nx)`，再按
  `sign(cos·tx + sin·ty)` 选与当前朝向**同侧**的那支（正对撞上切向速度≈0，不选分支会左右乱翻）；
  ③`vx/vy` 跟着新朝向重设，保持「速度与朝向一致」不变量。
- ⚠️ **②必须限速**（`SLIDE_TURN_PER_FRAME = 0.35` rad/帧，与常规转向同量级）：
  渲染是 `ctx.rotate(entity.angle)`，正面撞上切向与朝向最多差 90°，一帧扭过去**本身就是一次抽搐** ——
  修顿挫反而造出抽搐。这是「一次 Edit 改完之后才想起来的坑」，所以**改朝向/角度的写法前先确认渲染读的是它**。
- ⚠️ **趴着不动的（伏击/打盹）只推位置不改朝向**（`speed < 1e-4` 直接 continue），
  否则被推一下就会突兀扭头。
- **两遍处理**保留：障碍物成对重叠时单遍会把鱼从一块挤进另一块、来回抵消等于卡死。
- **验证**：单测 `src/__tests__/obstacle-slide.test.ts` 3 例（玩家贴岩 扫掠 2.67rad/贴面 185 帧/漂移 5.8px；
  AI 鱼 4.30rad/223 帧/5.1px；第 3 例钉「趴着不动的不扭头」）。**反向验证**：退回「只推位置」
  即刻失败（扫掠 0.00rad / 贴面 387 帧）。
- **浏览器证据**：`scripts/probe-obstacle-slide.mjs` —— 只留一块最大岩石、其它障碍/鱼/危险物挪走
  （**保持 PLAYING**，切 MENU 会卸载 GameCanvas），把玩家贴在岩石表面、鼠标持续指向圆心；
  实测 **90/90 帧贴面、切向滑走 309.6px、路程 419.9px、零页面错误**。截图 `obstacle-slide.png`

## 修复「碰到边缘会反弹」+ 两条约束通路收编（用户报「碰到边缘会反弹」）

- **根因**：`clampToMap` 硬分支和上一条（障碍物）一样只顾位置不顾朝向，而且更狠三点：
  ①`correctedDist = max(limit - buffer, limit*0.95)` —— **往内多拉一截**（刚越界 2px 被拉回
  **159.2px**），这一步就是体感上的「反弹」；②朝向按「朝圆心压缩到 40%」处理 → 正面撞上一帧甩
  **1.257 rad（72°）**；③缓入区还按穿透比例把朝向往圆心压，离边越近压得越狠。
- **治法**：硬分支**只推回表面**（`entity = CENTER + n*limit`）→ 朝向交给新抽出的
  `alignToSurface(nx, ny)`（限速 `SLIDE_TURN_PER_FRAME=0.35` rad/帧、取与当前朝向同侧的切向分支）
  → `vx/vy` 跟着重设；趴着不动（`speed<1e-4`）的只推位置不改朝向；缓入区**只减速、不动朝向**；
  障碍物侧的内联切向数学也换成同一个 `alignToSurface` —— **两条约束通路从此只有一份实现**。
  （上一条的收获是「边界做了、障碍物没做」的不对称；这轮反过来把它统一掉了。）
- ⚠️ **两条约束通路必须同向（踩出来的坑）**：硬分支改成「钉在 limit 上」后，实体每帧都在表面上
  （`penetrationRatio` 恒为 1），缓入区那个向心力变成**每帧满强度**地跟 `alignToSurface` 抢方向盘 ——
  `orbit.test` 当场报「PLANKTON 转 6.4 圈 半径 9.0px」。缓入区只管减速后才不打架。
- **验证**：单测 `boundary-slide.test.ts` 5 例（越界 2px 只回拉 2.0px / 单帧转角 0.350rad /

  用起点 limit 会严重少算（68/10 帧 vs 380/370 帧）；②**别拿「本地角位移」当滑走判据** ——
  30° 处 `dr/dθ≈1236px/rad`，贴边滑 186px 只折合 0.06rad，看着像没动；判据应是「贴边 + 路程显著」。
