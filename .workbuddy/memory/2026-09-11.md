## 多鱼塘阶段 2a：塘际传送门 + 世界重建（feat 见当日 commit）

- **切片决策**：阶段 2 原计划「参数化 WORLD_SIZE/形状」太重（`terrain.ts` 在**模块级**解构
  `MAP_SHAPE_CONFIG`，等于写死形状，调用点十几处），于是拆成 **2a 先做机制**（同尺寸世界、按塘重建内容）、
  **2b 再做尺寸/形状差异化**。「换塘」这套机制才是最值钱的部分。
- 机制：`Portal.kind` = `LOCAL`（塘内门，老行为）/ `POND`（塘际门）；每个「别的塘」一扇，
  摆在距中心 1150px 的环上、半径 ×1.4、名字「目标塘名·门」（琥珀虚线环 + 塘色核心，MiniMap 里是琥珀大点）。
- 新增 `world.ts → pondTravel(state, 目标塘, ctx?)`：
  **保留**玩家成长（体重/等级/技能/进化点数/装扮）+分数+计时+**战队成员**；
  **重建**障碍（按 `obstacleScale`：清水 1.0 / 珊瑚 1.6 / 深渊 0.6）/门/建筑；
  **清空**野鱼/道具/宝藏/危险/粒子/飘字；玩家回中心 + 落地保护 + 过场闪屏（40 帧，目标塘色）；
  传了 ctx 就复用 `spawnSystem` 铺底 12 条鱼。
- **语义收紧**：塘内门只在 `LOCAL` 里挑目标 —— 否则随机传送会把人丢到塘际门上，下一帧被动换塘。
- 排行榜加**分塘筛选**（各塘倍率不同，混着比不公平）。
- **踩坑 1（老坑重演，这次在源头解决）**：换塘后必须顺手 `player.currentBiome = getBiome(...)`，
  否则下一帧 worldSystem 会发「进入新海域」写气泡，把「进入 XX塘」顶掉。阶段 1 就是撤掉气泡躲开的，
  2a 直接在 `pondTravel` 里同步生态区。
- **踩坑 2**：`world.ts` 的 `teleportLockUntilFrame` 是**模块级**状态，会跨单测用例泄漏（前一个用例锁到
  time+120，后一个 time 从 0 开始就被锁死）→ 加 `__resetTeleportLock()`，用例开头调（同 squad 的
  `__resetSwitchCursor`）。
- **探针两条纪律**：① 别用严格相等断言「玩家回中心」—— 世界还在跑，鼠标转向会推走几像素 → 用容差；
  ② 别用即时 `count()` 读 HUD —— `uiState` 每 100ms 同步一次，会读到过期快照 → 用 `waitForSelector`。
- 验收：`pondTravel.test.ts` 13 例（含用**固定种子 LCG** 比较三个塘的障碍数量，可复现）；
  `probe-pond-travel.mjs` 全过（换塘 / 障碍 51→72 / 铺底 16 条鱼 / 闪屏 / 塘内门不换塘 / 规则面板）；
  全量 **227 例 / 17 文件** 绿、tsc 干净、build 347.07 kB（gzip 109.55 kB）、`__FISH_DEBUG__` 未泄漏。

## 环境（补充）

- 本机 bash 偶发抽风：`shell-runtime-bash-env.sh: dirname: command not found` → 后台任务直接启动失败
  （前景简单命令还行）。规避：改用 **PowerShell** 跑（PowerShell 工具本会话**不回显 stdout**，
  所以一律 `2>&1 | Out-File -Encoding utf8 文件` 再读文件）。vite dev server 也改成 PowerShell 后台起。
