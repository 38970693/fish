## 菜单溢出修复：第一个界面上下被切掉（用户报，附截图）

### 现象与根因
用户截图：主菜单（标题 / 选择鱼塘 / 选择初始鱼类 / 开始游戏 / 装扮 / 规则·成就·排行榜）**上下两头都被裁掉**，滚也滚不到。
根因两层叠加：
1. 根容器 `App.tsx` 是 `w-full h-screen overflow-hidden` —— 直接裁掉溢出部分；
2. 菜单是 `flex items-center justify-center` 且**不滚** —— 居中布局会让子元素上下同时溢出，而父级滚动条只能滚到下方那一半，
   所以标题被顶出视口就再也回不来。

### 修法（两层，缺一不可）
- 外层：`absolute inset-0 z-50` → 加 `overflow-y-auto overscroll-contain`（负责滚）；
- 内层加包裹：`min-h-full flex items-center justify-center p-3 sm:p-6`（矮时居中、高时把容器撑开交给外层滚）。
- 尺寸收敛（顺带解决「装不下」）：标题 `text-8xl` → `text-4xl sm:text-6xl lg:text-7xl`；卡片 `p-12` → `p-4 sm:p-6 lg:p-8`；
  间距 `gap-12` → `gap-3 sm:gap-4`；塘卡 `w-60 p-4` → `w-56 p-3`；初始鱼头像 `w-16` → `w-12 sm:w-14`；
  开始游戏 `text-4xl py-6 px-24` → `text-2xl sm:text-3xl py-3.5 px-14 sm:px-20`；其余按钮同法降档。
- 面板（规则 / 成就 / 排行榜 / 装扮）都是 `fixed inset-0`，不受滚动容器影响，无需改动。

### 回归锚（新增 e2e 1 例 → 套件 19 → 20）
`e2e/game-flow.spec.ts`「矮视口下菜单不裁切：头尾控件都能滚进视口」：
压视口 **1280×560** 制造溢出 → 先断言「菜单几何高度真的 > 视口高」（否则用例是空的）→ 再对标题与开始按钮
各做 `scrollIntoViewIfNeeded()` 后要求落在视口内。**只比几何量、不认 Tailwind 类名**，换布局写法也测得住。

**反向验证**：把外层摘回 `flex items-center justify-center`（内层 `contents`）→ 用例当场红，标题 `y = −132.75`
（与用户截图现象量化一致）；装回全绿。

### 验证
`tsc --noEmit` 干净 · 单测 **491/491（36 文件）** · e2e **20/20（22.5s，零重试）** · build **412.52 kB / gzip 131.15**。

### 补第二刀：光「能滚」还不够，得「放得下」
第一刀解决的是「滚不到」，但实测菜单内容高 **940px** —— 1440×900 视口下最后一行（规则/成就/排行榜）
仍被切掉半截，观感上还是用户报的那个毛病。所以再收一档纵向节奏：
菜单卡片 `lg:p-8→lg:p-6`、外层 `sm:p-6→sm:p-5`、标题 `lg:text-7xl→lg:text-6xl` + `sm:mb-6→sm:mb-4`、
分组 `gap-4→gap-3`、小标题 `text-2xl→text-xl`、鱼头像 `w-14→w-12`（图标 28→26）。
内容降到 **~888px** → 1440×900 直接整屏放下（实测 `scrollable=false`）；1280×560 溢出 380→288px，依旧可滚。
**教训：居中布局的「截断」有两层需求 —— ① 滚得到（可达性）② 装得下（观感）。只做①用户照样觉得"被切了"。**
